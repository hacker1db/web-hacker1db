# Skills catalog publishing

The website consumes `src/lib/server/skills-snapshot.json` at build time. Builds and visitors do not need private GitHub credentials. The committed snapshot is still a labeled preview; do not remove `sample: true` until the public entries have been reviewed.

## Import a reviewed export

Prepare a JSON export using the fields in the existing snapshot. Set `sample: false` and include `published: true` on every approved skill. Exclude all private/unpublished entries entirely. Keep operational SKILL.md bodies, reference files, personal paths and credentials out of the export. `sourceRevision` must be a full commit SHA from `hacker1db/skills`; sourcePath identifies each SKILL.md at that revision. Source checkout paths may change without changing the stable skill ID or `/skills/<id>/` URL.

```sh
bun scripts/import-skills.ts /path/to/reviewed-export.json /path/to/skills FULL_SOURCE_COMMIT_SHA
bun scripts/import-skills.ts /path/to/reviewed-export.json /path/to/skills FULL_SOURCE_COMMIT_SHA --check
```

The importer checks the schema, explicit publication flags, source revision and regular files at the pinned Git tree, then sorts skills/workflows for repeatable output. It never reads source bodies into the output or runs source scripts. Failed validation leaves the committed snapshot unchanged; successful imports use an atomic file rename. `--check` compares the committed snapshot without writing. The printed SHA-256 identifies the exact generated bytes. Review the Git diff before committing. This command verifies the provided export; it does not create curated descriptions, authorize publication or provide source-repo automation.

Run `bun test`, `pnpm check`, `pnpm lint` and `pnpm build`. Check `/skills/`, each generated detail page, and an unknown slug (404). Review HTML and serialized page data for accidental private fields. Source changes reach production only after the reviewed snapshot is committed and deployed. Revert that snapshot to roll back. Installation commands remain withheld until a distributable public bundle has been verified.

## Optional top video

Blog posts keep their existing `youtube: VIDEO_ID` frontmatter. An optional `transcriptUrl` may point to HTTPS on `hacker1db.dev` or `www.youtube.com`. The video appears below post metadata and above article prose, at 16:9. A post without a valid video keeps its existing thumbnail fallback; without either, prose follows metadata normally.

Skill entries use `video: { provider: "youtube", videoId: "VIDEO_ID", title: "Accessible video title", transcriptUrl: "https://hacker1db.dev/transcripts/example/" }`. Catalog videos use the same shape under `featuredVideo`. Omit optional fields entirely when unused.

The shared player starts as a local placeholder. It makes no thumbnail/player request to YouTube before the reader clicks Load video. The loaded iframe has no autoplay parameter or permission. Readers then use the native player controls, or the watch link. Transcript links are validated for every context, including blog frontmatter. Check playback and captions against a real video before release.

## Private local preview (no publication)

To inspect actual skills before publishing, point the development server at an existing local checkout of the private repository. No exported JSON, GitHub token, repository visibility change or publication flags are needed.

Create an **ignored** `.env.development.local` file in the blog checkout:

```sh
PRIVATE_SKILLS_PREVIEW_DIR=/absolute/path/to/private/skills/checkout
```

Run `pnpm dev --port 4179` and open `http://127.0.0.1:4179/skills/`. The server reads `skills/**/SKILL.md` on each refresh, including working-tree edits. It displays real frontmatter names/descriptions and the actual instructions as escaped plain text, without executing them or loading linked assets. Categories use source frontmatter when present and otherwise say Private skills. Editorial inputs/outputs and workflows are not invented. No private snapshot is written into the blog repository.

Private mode is restricted to loopback-bound Vite development. It rejects non-local hosts, hosted/CI environments, Vite production builds, Vite preview servers and CLI overrides that expose the dev server. Pages are no-store/noindex and development analytics are disabled. Private details are sent to the local browser only; do not share its contents or use a public tunnel. Delete or unset the local variable and restart dev to return to the committed sample catalog.

Normal production builds do not load `.env.development.local` and continue to use only the committed public/sample snapshot. Explicitly passing `PRIVATE_SKILLS_PREVIEW_DIR` into a production build fails before loading skills. Keep private instructions out of screenshots, plan uploads, Git commits and published exports.
